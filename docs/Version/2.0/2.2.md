### 🔐 Seize remarques de recette : domaines, RBAC, LDAP, tunnel, formation *(TO-DO 55 à 66)*

- ⚠️ **Connexion aux machines : seulement sous ses domaines principaux.** Le domaine tapé (`alice@test.fr`) doit être le domaine principal — les deux derniers labels — d'un groupe du compte. Un compte `auth` partout se connectait sous n'importe quel domaine existant, et `03_06` (clés pour sshd) ne vérifiait pas le domaine. Les comptes locaux créés sous un sous-domaine (`user@infra.acme.lan`) ne se reconnectent plus sous ce nom - Lorens Viguie
- 🌳 **Les domaines parents sont créés avec le groupe** (`create -g Web web.cloud.acme.lan` crée `acme.lan` et `cloud.acme.lan` s'ils manquent), rattrapés au démarrage sur une base existante ; le dernier groupe d'un domaine qui a des sous-domaines ne se supprime plus - Lorens Viguie
- 🔑 **Détacher n'est plus supprimer.** Nouveau verbe RBAC `remove` (colonne « Détacher ») : retirer un compte, une machine, une permission ou une GPO d'un groupe exige `write:remove:<objet>`, et non plus `write:delete:<objet>`. Migration unique : chaque droit `delete` est recopié en `remove`, portée comprise - Lorens Viguie
- 👁️ **L'arborescence web respecte le périmètre** (elle montrait tout l'annuaire, comptes compris, à qui détenait `write:eyes`) ; `eyes -g <domaine>` filtre les sous-domaines ; **la page Cluster exige `read:cluster`** - Lorens Viguie
- ⚠️ **LDAP et second facteur** : un compte MFA se lie avec son mot de passe **suivi** du code ; `ldap.mfa_bypass: true` rétablit le mot de passe seul, en le journalisant. LDAP contournait le second facteur par défaut. Une application liée avec un compte MFA est refusée à la mise à jour - Lorens Viguie
- 🔌 **Une déconnexion ne coupe plus le tunnel machine.** La fermeture PAM visait le tunnel `vaultaire` ; le `--fetch-key` de sshd effaçait la présence de la machine dans `status -c` ; et une seule session expirée effaçait **tout le parc** de `status -c` (toutes les machines sont connectées sous `vaultaire`). Le tunnel est ouvert au démarrage sur tout nœud, supervisé et relancé après panique ; le battement recrée la présence - Lorens Viguie
- 🌐 **GPO `dns_resolver` sur Rocky 9** : passe par NetworkManager (`[global-dns]`) quand systemd-resolved n'est pas actif, ou écrit `/etc/resolv.conf` ; plus aucun service démarré par effet de bord - Lorens Viguie
- 🎨 Les erreurs du portail s'affichent en rouge (huit pages les montraient en vert) - Lorens Viguie
- 🎓 **Formation** : `vaultaire` / `password` n'a jamais ouvert le portail — le jalon 1.3 se connecte avec `admin` et **donne** un mot de passe à `vaultaire` ; le jalon 3.2 fait couvrir l'IP de l'hôte par le certificat de l'API (sinon `vlt` échoue en x509), et l'alias passe en `docker exec -i` - Lorens Viguie
